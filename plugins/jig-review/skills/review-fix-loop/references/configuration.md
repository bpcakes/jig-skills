# Provider and validation configuration

Read when selecting external providers, configuring role environment variables, or opting into isolated validation. Native Codex with checkout validation needs no configuration file.

`init` also accepts the loop options and `--config /absolute/config.json`. Configuration is explicit JSON:

```json
{
  "reviewers": [{"id": "codex"}],
  "reviewConcurrency": 2
}
```

Without an explicit `timeoutMs`, bundled Claude/Cursor review workers allow 29 minutes: the adapter has its normal 28-minute overall budget, with one minute left for worker settlement. Other commands default to five minutes. An explicit `timeoutMs` overrides the worker budget for every role; a validation check's own `timeoutMs` overrides it for that check. The bundled adapter reserves the smaller of one minute or ten percent of the worker budget for settlement (at least one millisecond, with an adapter minimum of one millisecond). Very short explicit limits may expire during startup and cannot guarantee cleanup time.

Defaults are `validationMode: "checkout"` and `validationSandbox: "host"`: review, triage, and repair use the actual checkout, and direct repairs are validated there without a copy-and-apply phase. `validationMode: "isolated"` opts into private assignment and validation copies and selects Bubblewrap on Linux or Seatbelt (`sandbox-exec`) on macOS. Explicit `validationSandbox: "bubblewrap"` or `"seatbelt"` also implies isolated mode. Executable copies live outside the source checkout, under a durable per-run path in the system temporary directory. The sandbox hides or denies reads of original workspace source, permits the necessary read-only Git object stores, disables network access, and provides private writable home/cache/scratch paths. It does not copy ignored dependencies or construct a toolchain; use it only for an existing project workflow that supports this environment. Missing dependencies or a missing selected sandbox stop the workflow without fallback. Combining isolated validation with the host sandbox is unsupported and stops before run allocation; select checkout validation explicitly when using the existing prepared environment. Each run belongs to its original repository and host; resume it there. With per-round commits, isolated repairs are applied and committed before validation runs in a private copy of that tip; failed validation retains the published commit. Select `--commit-mode none` when failed isolated candidates must remain unpublished.

Only available capabilities enter provider selection. Explicit `--reviewers`/`--all-reviewers` pin a slot to every requested provider on every fresh pass; an unavailable or permanently failed selected provider prevents convergence. `status.providerCoverage` exposes requested/completed providers and retained permanent failures. `reviewConcurrency` accepts 1–3 (default 2); native boundaries expose all prepared requests in `assignments`. Independent reviewers share the same pinned source state, and repairs wait for the entire wave. Skipping an unavailable capability consumes no invocation or attempt ID; every counted reviewer attempt is a durable assignment. Strict policy still requires distinct available providers.

The existing checkout is not an unfiltered shell environment. Commands inherit a curated set of PATH, locale, proxy, home/cache, and common Java, Go, Rust, Node-version-manager, and Python-environment settings; the exact allowlist is `localEnvironment` in [job-runtime.mjs](../scripts/job-runtime.mjs). All commands force `CI=1` and `GIT_OPTIONAL_LOCKS=0`, including when the parent supplied other values. Review commands additionally inherit credentials/profile variables for their selected provider. `environmentFrom` maps roles (`review`, `triage`, `repair`, `validate`) to additional inherited variable names, for example `{"validate":["PYTHONPATH","CC","PROJECT_TEST_CONFIG"]}`. These names are otherwise omitted; this option does not override the forced CI/Git settings. Values are resolved at execution, not persisted in requests. Do not allow provider credentials into validation. Commands and transcripts must not print secrets.

A `codex` reviewer without `command` uses native host delegation. Selected Claude and Cursor reviewers without custom commands use [provider-bridge.mjs](../scripts/provider-bridge.mjs), which reads the assignment from stdin, invokes the existing provider adapter with its scope/access/model controls, and validates structured output and paged coverage receipts. Their `claude` or `cursor-agent` executable must be available on the review worker PATH. No handwritten per-task bridge is required. A custom `command` overrides the bundled bridge; it must emit exactly one JSON result and use a fresh session. Optional `triageCommand` and `repairCommand` use the same protocol. Provider IDs must be selected by `--reviewers`. Do not claim a provider ran without its completed report. Known authentication/configuration/quota errors return `retryable: false` and disable that provider for the run; uncertain execution still stops without replay.

Capability preflight checks executable files using the command's working-directory and role-PATH rules. Relative adapter paths refer to the assignment repository, which is the actual checkout by default and a private copy in isolated mode, rather than the controller's invocation directory. Required triage/repair executables and the selected sandbox's platform/executable compatibility are checked before publishing an active run. Preflight does not guarantee later authentication or sandbox permission success; later preparation failures become durable outcomes. Without explicit provider selection, balanced review attempts use configured provider order, rotating deterministically after failure; each slot has its own attempt cap. Strict excludes providers already represented in the current quorum and never downgrades to same-provider evidence. Models and profiles are assignment inputs; adapters must honor them. Provider-specific flags require explicit selection when that provider is not in the defaults: for example, `--claude-model` also needs `--reviewers claude,codex` under balanced policy.

Isolated validation retains read-only access to Git object alternates, including linked/shared repositories under temporary paths. Bubblewrap explicitly binds those object stores after concealing host `/tmp`; it does not grant source or object-store write access. This is Git access, not dependency provisioning.

Validation scratch is reserved before allocation under the external workspace root, just like a repository copy. Both sandboxes route `HOME`, XDG cache/config, and temporary-directory variables to this resource on the workspace root's filesystem. Bubblewrap binds it through the concealed `/tmp` mount. Commands share scratch within a validation cycle; recovery cycles get fresh scratch. Each cycle queues both resources for cleanup after command settlement on success, failure, and terminal cancellation. Resume reclaims abandoned reservations and retries interrupted cleanup without replaying validation. Active scratch from older records is also eligible for exact-path cleanup; unreferenced historical scratch remains part of the retained record until explicit pruning.


## Prerequisites and generated evidence

Optional `prerequisites` is an array of `{ "id": "toolchain", "argv": ["node", "--version"], "timeoutMs": 10000 }` checks executed before discovery. IDs must differ from `requiredValidation` IDs. They use the validation worker's cwd, environment, sandbox, process tracking, and logs, and cannot be optional. Failure stops before reviewer work; prerequisite success does not replace required validation.

Both prerequisite and validation entries may declare `requiredEnvironment: ["DATABASE_URL"]`. Missing or empty variables for required checks in the sanitized worker environment stop initialization; every check verifies them again before execution. Optional checks with missing variables record a startup failure without blocking acceptance. Export required values through the existing environment and add non-default names to `config.environmentFrom.validate`. The contract stores names, never values. Connectivity or toolchain probes should be cheap, read-only prerequisite commands. Pin locally available CI gates from AGENTS.md, CONTRIBUTING.md, project contracts and CI configuration before initializing; discovery suggests evidence, never silently runs it.

Optional `evidenceOutputs: [{ "path": ".agent/state/receipts.jsonl", "format": "jsonl" }]` declares exact generated data paths. During checkout repair, only appended complete JSON objects with unchanged prior bytes, file kind, and permissions may cross an excluded-path boundary. Exclude these outputs from `workspaceEdits`; the controller records their before/after evidence separately and validates/reviews the combined checkout. Wildcards, policy files, overwrites and deletions are rejected. These records do not become controller receipts, and path declarations do not prove that tests or source ignore their contents. Per-round commit mode still requires a clean included commit scope; choose `none` when excluded outputs must remain uncommitted.
