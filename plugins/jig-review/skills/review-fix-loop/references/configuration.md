# Provider and validation configuration

Read when selecting external providers, configuring role environment variables, or opting into isolated validation. Native Codex with checkout validation needs no configuration file.

`init` also accepts the loop options and `--config /absolute/config.json`. Configuration is explicit JSON:

```json
{
  "reviewers": [{"id": "codex"}],
  "timeoutMs": 300000
}
```

Defaults are `validationMode: "checkout"` and `validationSandbox: "host"`: review, triage, and repair use the actual checkout, and direct repairs are validated there without a copy-and-apply phase. `validationMode: "isolated"` opts into private assignment and validation copies and selects Bubblewrap on Linux or Seatbelt (`sandbox-exec`) on macOS. Explicit `validationSandbox: "bubblewrap"` or `"seatbelt"` also implies isolated mode. Executable copies live outside the source checkout, under a durable per-run path in the system temporary directory. The sandbox hides or denies reads of original workspace source, permits the necessary read-only Git object stores, disables network access, and provides private writable home/cache/scratch paths. It does not copy ignored dependencies or construct a toolchain; use it only for an existing project workflow that supports this environment. Missing dependencies or a missing selected sandbox stop the workflow without fallback. Combining isolated validation with the host sandbox is unsupported and stops before run allocation; select checkout validation explicitly when using the existing prepared environment. Each run belongs to its original repository and host; resume it there.

Only available capabilities enter provider selection. Skipping an unavailable capability consumes no invocation or attempt ID; every counted reviewer attempt is a durable assignment. Strict policy still requires distinct available providers.

The existing checkout is not an unfiltered shell environment. Commands inherit a curated set of PATH, locale, proxy, home/cache, and common Java, Go, Rust, Node-version-manager, and Python-environment settings; the exact allowlist is `localEnvironment` in [job-runtime.mjs](../scripts/job-runtime.mjs). All commands force `CI=1` and `GIT_OPTIONAL_LOCKS=0`, including when the parent supplied other values. Review commands additionally inherit credentials/profile variables for their selected provider. `environmentFrom` maps roles (`review`, `triage`, `repair`, `validate`) to additional inherited variable names, for example `{"validate":["PYTHONPATH","CC","PROJECT_TEST_CONFIG"]}`. These names are otherwise omitted; this option does not override the forced CI/Git settings. Values are resolved at execution, not persisted in requests. Do not allow provider credentials into validation. Commands and transcripts must not print secrets.

A `codex` reviewer without `command` uses native host delegation. External providers require `command` with adapter argv; an unconfigured external provider is unavailable, never relabeled native Codex. The adapter reads the assignment as JSON from stdin and emits exactly one JSON result on stdout, and must start a fresh session for each assignment. Provider IDs must be selected by `--reviewers`. Optional `triageCommand` and `repairCommand` use the same protocol. The bundled comprehensive-review CLIs emit prose and are not directly compatible JSON adapters: a bridge must pass the task contract and convert a complete report into this schema without dropping findings or coverage limitations. Do not claim an external provider ran without a configured bridge executing it.

Capability preflight checks executable files using the command's working-directory and role-PATH rules. Relative adapter paths refer to the assignment repository, which is the actual checkout by default and a private copy in isolated mode, rather than the controller's invocation directory. Required triage/repair executables and the selected sandbox's platform/executable compatibility are checked before publishing an active run. Preflight does not guarantee later authentication or sandbox permission success; later preparation failures become durable outcomes. Balanced review attempts use configured provider order, rotating deterministically after failure; each slot has its own attempt cap. Strict excludes providers already represented in the current quorum and never downgrades to same-provider evidence. Models and profiles are assignment inputs; adapters must honor them. Provider-specific flags require explicit selection when that provider is not in the defaults: for example, `--claude-model` also needs `--reviewers claude,codex` under balanced policy.

Isolated validation retains read-only access to Git object alternates, including linked/shared repositories under temporary paths. Bubblewrap explicitly binds those object stores after concealing host `/tmp`; it does not grant source or object-store write access. This is Git access, not dependency provisioning.

Validation scratch is reserved before allocation under the external workspace root, just like a repository copy. Both sandboxes route `HOME`, XDG cache/config, and temporary-directory variables to this resource on the workspace root's filesystem. Bubblewrap binds it through the concealed `/tmp` mount. Commands share scratch within a validation cycle; recovery cycles get fresh scratch. Each cycle queues both resources for cleanup after command settlement on success, failure, and terminal cancellation. Resume reclaims abandoned reservations and retries interrupted cleanup without replaying validation. Active scratch from older records is also eligible for exact-path cleanup; unreferenced historical scratch remains part of the retained record until explicit pruning.
